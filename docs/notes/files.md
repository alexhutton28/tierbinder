# Files

Part of TierBinder's notes, indexed in `CLAUDE.md`. Keep them matching the code in the same PR that changes it.

All paths are in `src/app/`.

- `Editor.tsx`: the shell, shared by every graphic: the stage and its scaling, selection and its outline, the card menu, the Add Cards tab (search, picking, dragging results, bulk import), the Customize tab (laid out in sections like Add Cards: each a `flex flex-col gap-3` div, heading first, in a `gap-4` panel with a hairline between sections (`.tierbinder-sections` in `globals.css`), toggles after its other settings, and every setting a row (`.tierbinder-prop`: its label at the left, its control at the right, every control's right edge in line): first Board: the Type dropdown (each type with its icon) and Shape, both `Dropdown`'s `prop` rows, then Clear (a `quiet` `ClearButton`, "Clear board" to screen readers) under them at the left, so the heading has nothing beside it and sits where every tab's first heading does; then the graphic's `Settings` (what's on the board); then Style, holding the graphic's `BoardSettings` (how it looks); then Card Tray (its heading a `Toggle`, "Card Tray" and its switch at the row's end; Tray Color while it's on; its cards are cleared from Clear). Save & Share is laid out the same way: Image (help text under its heading: the board's shape and where it's best posted, from `shapeOf` in `canvas/size.ts`, whose `SHAPES` carry a `bestFor`; its buttons, then Include Card Tray in Export, after them), then Board Link), the Save & Share tab (export and share links, see Share links), the shared-board dialog, autosave. If a link's board type has never been used on this device, opening it makes that type's board first. It only talks to graphics through `GraphicType`.
- Headings (`Editor.tsx`): a hidden `h1` (TierBinder), a hidden `h2` opening each tab panel and the board, the panels' sections `h3`. `.tierbinder-sections` puts its hairlines only between visible sections, skipping hidden headings and statuses.
- `document.ts`: the saved document (`{ version: 3, kind, graphics }`), `currentGraphic`, and `parseSaved`, which converts older saves.
- `graphics/types.ts`: the `GraphicType` interface; `graphics/index.ts`: the list of types (`GRAPHIC_TYPES`), the `Graphic` union, and `typeOf(kind)`.
- `graphics/tier-list/`: `model.ts` (document, layout, edits, import, parse), `TierListCanvas.tsx`, `TierListSettings.tsx`, and `index.ts` (its `GraphicType`).
- `graphics/blank/`: the same for the blank canvas (`BlankCanvasView.tsx`, `BlankSettings.tsx`).
- `canvas/CardNode.tsx`: a card on the board for every graphic (image or split card, rounded clip, placeholder, dragging, menu clicks). `canvas/size.ts`: the board's height, its shapes (their widths and export sizes) and card sizes.
- `canvas/keyboard.ts`: `nextCard`, the card the arrow keys pick next, and `ARROWS` (see Keyboard on the board).
- `canvas/tray.ts`: the card tray's model (`Tray`, saved as each graphic's `tray`; layout, drop index, edits); `canvas/CardTray.tsx` draws it. The editor owns it for every graphic (see Card tray).
- `cards.ts`: card types saved in documents (`CardFace`, `CardItem`), `newId`, client calls to the API routes, bulk import lookups (`resolveCard`, `defaultPrint`), and image loading through the proxy.
- `importText.ts`: the bulk import format (documented at the top of the file): cards before the first `#` (the card tray, or the board: `ungroupedImport`), then `#` groups for the board.
- `ui/Button.tsx`: the page's buttons, with a `variant` (`default`, `primary`, `tool`, `icon`: square, holding only an icon, so it needs an `aria-label` and a `title`; `quiet`: an `icon` button with no box, muted until hovered (a tier's remove); `text`: just its words and any icon beside them, brightening on hover), and a `size`: `large` is a section's closing action below `b7`, 44px tall (`--tb-touch-target`) with its parent setting its width (a `grid`, `b7:flex`: spanning the panel, two splitting it), a control's height from `b7` up except on touch screens (Save & Share's buttons, Import, the shared-board dialog's answers).
- `ui/RadioBar.tsx`: the main nav, its tabs linked to their panels by id (`id`, a prefix: `tabId` and `panelId` give the ids, `TAB_PREFIX` in `Editor.tsx`; each panel is labelled by its tab). Each option has an icon from `public/`, drawn in the text color. A block in each option's color hugs the selected icon and word, measured from them, and springs to the next; left and right arrow keys move it. When the tabs don't fit, they show icons with only the selected tab named, then only icons (hidden labels are tooltips and stay for screen readers): hidden copies of the bar in each wider mode are measured against its space (`.sizers` in `RadioBar.module.css`), so the switch follows the real text widths. Labels fold and open by transitioning `max-width` to each label's measured width (`--label-width`), on the block's spring; the block's target comes from the hidden copy for the current step and selection, so it slides straight to where the name settles instead of chasing it.
- `ui/reveal.ts`: scrolling what just opened into view (in whatever scrolls it: the sidebar's tab panel beside the board, the whole sidebar under `b8`), only down, only as far as needed with 16px under it, never past its top: `revealBelow` (a smooth scroll, for Card Tray's rows when its toggle turns it on, once the tray under the board has slid in) `toTopThen` (back to a box's top, smoothly, then running what would change its contents: clearing the search on phones) and `followOpen` (Bulk Import: the panel follows its foot down each frame as it slides open, since the panel isn't tall enough to scroll there until it is).
- `ui/Toggle.tsx`: the settings' on/off switches (the Customize tab's), a `role="switch"` button: a pill track (`--tb-toggle-width` × `--tb-toggle-height`) in the fields' colors with a muted knob, the primary color with a dark knob when on, the knob sliding on `--ease-slide`; a setting's row, its words at the left and the switch at the right, the button spanning the section, a 44px touch target on touch screens giving the extra back as negative margin. As a section's `heading` (inside its `h3`, a `flex flex-col` so it spans it, when it turns the whole section on or off: Card Tray's), its words are in the heading's style, and it's no taller than the heading's line.
- `ui/Segmented.tsx`: a segmented control (the Style section's Label Width: S, M, L), a setting's row with its segments joined in one box in the fields' colors at the right, the chosen one lit in `--tb-segment-on`. Native radio buttons underneath (visually hidden), so Tab reaches the group once and the arrows move the choice; each option's `short` words show, and its full `label` ("Large: 170 pixels wide") is the tooltip and what screen readers hear; a 44px touch target on touch screens. `compact` drops the row: the segments alone, `label` naming the group for screen readers (the search results' size).
- `ui/ClearButton.tsx`: Customize's Clear (`quiet`: a muted text button, the last thing in the Board section, under Type and Shape; `label` names it for screen readers): Feather's trash (`public/trash.svg`) before the words, opening a menu under it (floating like a dropdown's list, `useAnchored`) whose `choices` each name a clear ("Clear Card Tray", "Reset Board Styles") and do it (`onSelect`), as the card menu's Clear Card Tray flyout does; with none it's disabled, and a choice that leaves none sends focus to `onEmptied` (the board). A second click, Escape, Tab or a press outside closes it; opening focuses the first choice, and the arrows, Home and End move through them; once one's done, focus goes back to the button unless it moved focus elsewhere.
- `ui/Checkbox.tsx`: every checkbox (picking from a list: the Sets popup; settings use `Toggle`), drawn in CSS instead of the browser's own: a box in the fields' colors, ticked in the primary color with a dark check, or in a given `color` with a white or dark check (`check`, else by contrast), as the Sets popup's tier colors are. The row is the label; on touch screens it's a 44px touch target that gives the extra height back as negative margin (the Sets popup's rows keep it).
- `ui/ColorField.tsx`: a swatch that opens our own color picker in a floating popup like a dropdown's (`useAnchored`, `usePopup`), never the browser's native one: first a compact, `small` `Segmented` at the left (no box, `--tb-control-height-small`, 24px; 44px wide on touch screens) of two icons (Feather's `grid.svg` and `droplet.svg`, each named in its tooltip; a `Segmented` option's `icon`) switching between two views, Swatches and Spectrum (the saturation and brightness square over a hue bar), the last one used saved per device (`tierbinder-color-view` in `localStorage`, Swatches by default). Swatches (`Swatches`, from `ui/swatches.ts`) is a grid of recommended colors, a column per hue (red, orange, yellow, green, blue, Storm, purple, pink, Petrel), five shades each, palest at the top: the tiers' colors in the middle, mixed toward white and black (`SHADE_MIX`: two paler, two darker), and the design system's own Storm and Petrel shades; every hue in one row of nine small columns across the picker (about 20px each), on touch screens too (`SWATCH_COLUMNS`, set on the grid as `--columns`, each swatch placed with `--column` and `--row`). It's a radio group, as the WAI-ARIA pattern has it: one Tab stop (the color in use, ringed, else the first), the arrows (as laid out), Home and End moving and picking, as do a click, Enter and Space; picking keeps the popup open. The view is shared by every color field on the page (`useSyncExternalStore` over a module-level value). Spectrum is `react-colorful`'s `HexColorPicker` (a saturation and brightness square over a hue bar, restyled in `ColorField.module.css` through `:global`, its handles kept inside by insetting the part that reads the pointer, with a `::before` band that still takes presses at the edge), switching between them growing or shrinking the picker: both views stay mounted, stacked in one cell (`.views`), the box easing to the shown one's height (set from a layout effect) as it grows in from its top and the other shrinks away to `--view-shrunk` and fades (`.view`, `data-active`; the hidden one `inert`); then one field across the picker (`.colorField`), its format a `text` `Dropdown` at its left edge (Hex, RGB or HSL; `tierbinder-color-format` in `localStorage`, shared like the view: `sharedChoice`; `Dropdown`'s `variant` and `buttonClassName`), a full-height hairline after it, then the hex code (the only hex field: there's none outside the popup) or three borderless number fields, a shorter hairline between them (8px in from the field's top and foot), each named in its tooltip; the format muted, the fields in Figtree with tabular figures, so the numbers don't outweigh the rest (`ChannelInputs`: applying once all three are in range; a color they sent doesn't reset them, so HSL's rounding doesn't move the other two while one is typed) (Board Colors, the board's own colors to pick in one click, were taken out for now). With a `name`, it's a setting's row, the name at the left and the swatch at the right, one button that opens it, placed from the swatch (the Customize tab's colors, lighting up on hover like an option, reaching 4px past the section on each side so the name and swatch line up with the other rows); without, the swatch alone (a tier's, before its name field; the pen's). Opening focuses the view's own control (the swatch in use, or the first; or the square, whose arrow keys move the color) except on touch screens; Escape, a press outside or Tab past it closes it, and Delete and Backspace in it don't reach the board. Dragging applies the color once a frame.
- `ui/Working.tsx`: a button's words while what it started is under way (Save & Share's buttons: "Downloading", "Copying" or "Sharing" and three dots hopping in turn, still under reduced motion), laid out in one cell with the button's own words so its width holds, the two crossfading over `--duration-hover` (instant under reduced motion).
- `ui/SidebarHandle.tsx`: the sidebar's resize handle (from `b8` up). Saves the width as a share of the window in `localStorage` (`tierbinder-sidebar`) and sets it on the sidebar column (`.sideColumn`: the header and the sidebar) as `--tb-sidebar-width` (a `vw` value), which that rule in `Editor.module.css` uses, falling back to `--tb-sidebar-default`. `Editor.tsx` sets that default on the column from the main nav's measured full width (`RadioBar`'s `onFullWidth`), plus the hide button and its 4px gap, 8px each side and the edge line, so the nav fits with every label; `globals.css` has a 400px stand-in until then. Its limits are a `clamp()` in that CSS: at least `--tb-sidebar-min` (250px) and at most the window less `--tb-workspace-min` (`b5`, 512px), the minimum winning; a drag past either is saved at the limit, and the readout shows the width the sidebar really has. Double-click resets; it's also a focusable `separator` (WAI-ARIA window splitter) that the left and right arrows move.
- `ui/SearchFilters.tsx`: the card search's Sets button (with the Clear sets half that slides out of it: `.split`, `.splitMain`, `.splitEnd`) (the filter icon, then "Sets", the ticked set's name, or the first one's and how many more: "Delta Reign +2", in full when it fits, else cut short with an ellipsis (`.setsLabel`; Sets and the Add to picker share a group that doesn't wrap, both shrinking, the picker's name truncating too), every ticked set's name in its tooltip; a set too new to be listed shows its code) and popup (a search of set names and codes, with a clear button while it has text, over a scrolling list of every set to tick; ticked boxes (`Checkbox`: a white check on the default tier colors, else white or dark by contrast) take the board's tier colors in the order they were ticked, looping, or a new tier list's on the blank canvas), opening like a dropdown, scrolled to put the first ticked set in the list at the top. Opening focuses its search except on touch screens (it would bring up the keyboard over the list); on touch screens each row is a 44px touch target (`--tb-touch-target`). The popup floats, as the dropdowns' lists do (`ui/anchored.ts`). `searchOptions.ts`: the search's options (`sets`, `reverse`), `MAX_SETS` (40: the route refuses more, and the popup stops ticking there), and how they travel as `/api/search` query parameters (`sets=TWM,PRE`, sorted so the same sets share a cached URL; `reverse=1`). `sets.ts`: the sets to filter by, one per code, newest first, from `api/tcgdex-sets.json`, leaving out codes marked `empty`.
- `ui/anchored.ts`: `usePopup`, the open state every floating popup shares (the dropdowns, the Sets popup, the color picker): kept on screen `FOLD_CLEARANCE` while it folds closed, and closed by a press outside its box. `useAnchored`, which shows a popup (a `popover`, styled `.tierbinder-anchored` in `globals.css`) in the top layer under its button, so it floats over the board instead of being clipped by, or widening, the sidebar: the button's edges and width and the popup's width go to the CSS (`--anchor-*`, updated on scroll and resize), which keeps it 8px inside the window. It opens above the button instead when it doesn't fit below and there's more room above (`data-side`), and dropdown lists scroll when the window is too short. A button whose popup is open (`aria-expanded`) keeps its hover color.
- `ui/pointer.ts`: `TOUCH_SLOP` (8px), how far a touch moves before it's a move: a result's long press is cancelled past it, and the one-row card tray decides there between panning and dragging.
- `ui/useReveal.ts`: `useReveal`, the card tray's slide in and out (see Card tray).
- `ui/flights.ts`: `launchFlights`, cards flying from the sidebar to the board or the card tray (copies drawn in plain DOM over the page, `flights.module.css`), and `wholeOnScreen`; see Flying in.
- `ui/Dropdown.tsx`: a labeled dropdown (its label beside it, or as a setting's row with `prop`: `.tierbinder-prop`, the label at the left and the dropdown at the right; Customize's Type and Shape) (the Add to picker and the board type) in place of a native `<select>`, where an option with a `color` shows it as a swatch before its name (the tiers: a rounded box as big as Feather's square icon, in an icon-sized space, with a light stroke in `--tb-muted` when the option is `outlined`, as the card tray's is, since it's a shade of the board; its list's rows have 8px at each end; a hidden label becomes the tooltip; `chevron={false}` drops the arrow, as the Add to picker does; `swatchOnly` shows only the chosen option's swatch in a button as tall as what's beside it with 8px at its sides, at least 44px wide on touch screens (not squared by `aspect-ratio`, which Safari doesn't size from a stretched height), its label and option the tooltip and what screen readers hear: the pinned search's Add to), so it can open and close with the card menu's animation (top to bottom); arrow keys, Enter/Space and Escape work as in a select.
- `THIRD_PARTY_NOTICES.md` (repo root): the licenses of TCGdex's data and Feather's icons, and the Pokémon trademark disclaimer. The sidebar's foot (`ui/Credits.tsx`, only under Save & Share, at every width, so the other tabs keep the height) says "Cards from TCGdex" with an info button 4px after the link, as tall as the text, that opens the full credits and the disclaimer (TierBinder isn't affiliated with Nintendo, Creatures, GAME FREAK or The Pokémon Company) in a floating popup (`useAnchored`), until the credits get a better home.
- `share.ts`: share links (`shareLink`, `readShareHash`, `isShareHash`); see Share links.
- `text.ts`: `titleCase`, for labels kept in sentence case in code (see Capitalization in the design system).
- `color.ts`: contrast helpers for drawing on user-chosen colors (`luminance`, `darkReadsBetter`), used by the Sets ticks and the card tray's hint.
- `Loader.tsx`: loads `Editor` with `ssr: false` (Konva needs a browser canvas), showing the editor's frame until it arrives (`Loading`, `Loader.module.css`): the top bar with the logo, the sidebar, and a 16:9 board-shaped placeholder shimmering as search results do, laid out as the editor is at each width; if the code fails to load, "Couldn't Load TierBinder; Reload the Page" in its place.
- `layout.tsx`: the root layout: fonts (Inter Black for tier labels, Figtree for the controls), metadata, analytics (`Measure.tsx`: Vercel Analytics and Speed Insights, sending each URL without its fragment, so a share link's board isn't reported) and the scroll container.
- Interface styles: a component's own CSS is a CSS Module beside it (`Editor.module.css`, `ui/RadioBar.module.css`, and so on), with camelCase class names used as `styles.name`; a module that uses a breakpoint (`@variant b8`) starts with `@reference` to `globals.css`. `globals.css` keeps the tokens, the `--tb-*` roles and sizes on `body` (change the look through those), base rules, and the `.tierbinder-*` rules more than one component uses (page, panel, heading, prop, field, clear button, popup, option, menu, focus ring).
- `api/`: `card` (by set + number), `search` (by name, or every card in some sets), `image` (proxy); `cardSource.ts`, which they call, which filters and sorts what `tcgdex.ts` finds (the TCGdex API, with `tcgdex-sets.json`: set codes, names and dates, also used by the page for the set filter, and `extra-images.json`, read only by the API: images for cards the API gives none, both from `npm run tcgdex:sets`, which also lists the TCG Pocket sets it leaves out in `tcgdex-skipped.json` so lookups don't take them for new sets).
