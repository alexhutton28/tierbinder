# Saving

Part of TierBinder's notes, indexed in `CLAUDE.md`. Keep them matching the code in the same PR that changes it.

- The document autosaves to `localStorage` (`tierbinder-doc`) silently and is read back with `parseSaved`; there's no file save/load. If a save fails (storage full or blocked) it toasts "Couldn't Save Changes on This Device", once until a save works again (`saveFailed`), as a line added to a toast already showing (a clear's, keeping its Undo) rather than replacing it. It holds one board per type (`graphics`, keyed by kind) and which one is showing (`kind`, whose board is always present). Cards are saved as names and image URLs, so even full boards are a few KB. The image proxy only allows today's hosts, so a board saved with Limitless image URLs (before November 2026) would show those cards as placeholders; no such boards were in use when Limitless was dropped.
- Version 1 was a tier list on its own (`{ version: 1, kind: 'tier-list', ... }`) and version 2 one graphic (`{ version: 2, graphic }`); `parseSaved` converts both. A saved board that doesn't parse is dropped and starts new, keeping the others.
- Changing the document's shape means bumping `version` and converting in `parseSaved`; a graphic's new setting with a default can instead be filled in by its `parse` (as the tier list's `border` and `tierCardBorders` are).
- Boards are parsed strictly (`parseGraphic` in `document.ts`, each type's `parse`, `parseTray`), since a share link's board comes from anywhere: every card goes through `parseCardItem` (`cards.ts`: a name and image are required, split halves must parse, a missing id is made), tiers keep only their id, name, color and cards, and a blank canvas's cards need finite `x` and `y` (then moved onto the board, its card size capped to it: `setCardShape`) and its strokes a tool and an even run of finite points. Colors are kept only as `#rrggbb` (`parseColor` in `color.ts`), else the default, since they reach CSS backgrounds and a `url()` would load from another host; pen, eraser and stroke widths are kept in range. A card or stroke that doesn't parse is dropped, not the board.
- In `next dev`, a tab left open while the document shape changes keeps its old in-memory board (without the new fields) until it's reloaded.
