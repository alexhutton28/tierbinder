# Graphic types

Part of TierBinder's notes, indexed in `CLAUDE.md`. Keep them matching the code in the same PR that changes it.

A type (`GraphicType` in `graphics/types.ts`) owns its document, how it draws, its settings and where cards go; the editor owns everything else. What the editor asks of a type:

- `ungroupedImport`: where bulk import's cards before the first `#` go, `tray` or `board` (as one more group in front).
- `create`, `parse` (a saved graphic of its kind, with later settings filled in), `label` and `icon` (in the board type dropdown; the icon a 16px SVG in `public/`, drawn in the text color), `targetNoun` (as in "Add to tier").
- `Canvas`: Konva layers drawn inside the editor's stage (passing `arriving` on to `CardNode`'s `hidden`, for cards flying in), with a `Rect` named `background` (pressing it deselects) and cards drawn with `CardNode`. It gets callbacks to change the graphic, select cards, open the card menu, pick a target and open a setting, and `onCardDrop`, which a dragged card's drop goes through first: it returns true when the editor took the card into the card tray, and the graphic leaves it be.
- Every graphic's document has a `shape` (`parseShape` in its `parse`, `DEFAULT_SHAPE` in `create`), which the editor reads for the board's width and the type changes through `reshape` (everything on the board kept and still on it: the blank canvas moves cards back on, the tier list just sets it). It also has a `tray` (`parseTray` in its `parse`, `defaultTray` in `create`, with the type's own default color), and a `border` the tray uses for split cards.
- `Toolbar` (optional): tools beyond moving cards, shown under the board, and `toolSettings`, the keys of their settings saved with the board, which undo leaves be. The editor keeps the active tool (`DEFAULT_TOOL`, `move`, until the toolbar picks another; reset when the board type changes) and passes it to the canvas as `tool`.
- `BoardSettings`: its rows in the Customize tab's Style section (how the board looks: its sizes, colors as named `ColorField`s, which also tell screen readers the hex, and border toggles), after its own `Settings` sections. `focus` keys go to `Settings`.
- `Settings`: its own sections of the Customize tab, after Board and before Style. `onEditSetting(key)` from the canvas switches to the Customize tab and passes `focus` to it (the tier list uses `tier:<index>`). It returns its sections, each a `flex flex-col gap-3` div with its heading first and toggles (`Toggle`) last: the panel puts 16px between whatever it returns.
- `moveCardTo` (optional): moves a board card to the end of a target, for a tier clicked while a card is selected; the blank canvas has none, so its cards only move into the card tray that way.
- `selectedId` (in `CanvasProps`): the canvas draws the selected card last (`selectedLast` in `graphics/types.ts`, reordering only what React draws, never the document), so it shows over cards that overlap it; the card tray does the same. Exports deselect first, so they keep the real order.
- `describe`: what's on the board for screen readers, to whom the canvas is one image: each place (a tier, the canvas) with its cards, and a `note` (the blank canvas's ink). The editor lists them, the card tray last while it shows, in a hidden list just before the board's box (`describeBoard`, from `placesOf`, each card by `cardLabel` in `cards.ts`), under a hidden `h2` naming the type, with the board's keys (`board-keys`, its description).
- `nudgeCard`: a board card moved a step from the keyboard (Alt and the arrows; see Keyboard on the board): the tier list along its tier or into the next at the same place in the row, the blank canvas `NUDGE` (10) design pixels, 1 with Shift. It gives the graphic back as it was where the card can't go further, and null for down past the board's foot, where the editor takes it into the card tray.
- Cards: `layout` (every card with its top-left corner and box, drawing order; the editor uses it for selection, hit-testing drops and export), `mapCards` (change or remove), `hasContents`, `clear` and `restyle` (whether anything's on the board, the board without it, styles kept, and the board with a new one's styles, its names, colors, card size and card tray color, everything on it kept: Clear Board's choices), `targets` (the Add to choices, each a name, an optional color for its swatch and an optional `id`, which keeps the chosen one chosen as others come and go; hidden when there's only one), `addCard` (to a target), `dropCard` (at a point), `importCards` (bulk import's `#` groups). Adding returns the new graphic or `{ error }` (the card tray is full), shown as a toast: one short message at the top of the window that fades after `TOAST_DURATION` (5s, plus `TOAST_LINE_DURATION`, 1.5s, for each line past the first; one offering Undo is held up while it's hovered or focused, by its id, `heldToast`). A toast for a change to the board (Clear Board's choices, Clear Card Tray, Hide Card Tray, a pool's cards added or removed, an import that added any: `showToast`'s `undo`) ends in an Undo text button in the primary color, which undoes it as ⌘Z does; it shows only until the board changes again or the board type switches (the history effect moves `toast.undo` from `waiting` to `armed`, then drops it), so it never undoes something else, and the change it reports always starts a step of its own. Screen readers hear "(Command+Z to undo)" after the message, the button is labeled "Undo: Board Cleared", and using it sends focus to the board. Every message is a toast, never text on or under the board: a full card tray, bulk import ("Importing…", which stays until its result replaces it, then how many cards went where and a line for each problem, up to `MAX_TOAST_PROBLEMS` (4) and then how many more; "Couldn't Import; Try Again" if a lookup fails outright) and copying. The screen reader copy is a new element each showing, so the same message again is read again. Only one shows at a time: another message replaces it, and the same one again restarts its timer without replaying its entrance, so rage clicks don't pile up (`toast` in `Editor.tsx`, `.toast` in `Editor.module.css`). Screen readers get it from a hidden live region that's always mounted; the visible toast is `aria-hidden`.

## Adding a graphic type

1. Add `graphics/<kind>/` with a model (document type with a unique `kind`, defaults, parse, layout and edits), a canvas, settings (`BoardSettings` and `Settings`), an icon in `public/`, a `describe` for screen readers, a `nudgeCard` for the keyboard, and an `index.ts` exporting its `GraphicType`.
2. Add it to `GRAPHIC_TYPES` and to the `Graphic` union in `graphics/index.ts`. The board type dropdown lists it, and saves of it load with no other changes.
3. Add `docs/notes/<kind>.md` with its notes, and a line for it in `CLAUDE.md`'s Notes index.
