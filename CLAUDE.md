# TierBinder

Alex Hutton's TCG graphics tool, live at tierbinder.big-a.fun and kept out of search with
`noindex` until it has its real domain. The goal is to be the best TCG tier list maker;
other graphics are a bonus. It moved here from big-a-website, whose issues and PRs old
commits link to. Next.js 16 (App Router, Turbopack), React 19, Tailwind CSS v4, Konva,
deployed on Vercel's Hobby plan.

## Workflow

- `main` is protected: changes go through a PR and must pass the `build` check. What it runs is in `.github/workflows/ci.yml`; run the same checks locally before committing, plus `npx prettier --write` on changed files and `npx tsc --noEmit`.
- Before calling a PR done, run the independent reviewers in `.claude/agents/` on its diff: `code-reviewer`, and `design-reviewer` when the interface changed. They haven't seen the work, so they catch what its author misses. Check their findings against the code, fix the clear ones, and ask Alex about any that need a decision. Don't request GitHub Copilot reviews on this repo: Alex's Copilot access isn't his to spend on it.
- Squash-merge and delete the branch.
- Don't stack PRs.
- Run tools from the repo folder.
- Dependabot opens weekly grouped minor/patch PRs; merge them once green.
- When a PR changes a convention described here, update the notes in the same PR.
- After changing `design/hutton-design-system.md`, run `npm run design:tokens` and commit `design/theme.css`. It needs the `hutton-design` skill installed. Never edit that file by hand.
- **Remind Alex to refresh the card data.** At the start of a session, check when `src/app/api/tcgdex-sets.json` was last committed (`git log -1 --format=%cs -- src/app/api/tcgdex-sets.json`). If it's over a month old, or a new English set has come out since, remind him to run `npm run tcgdex:sets` and commit `tcgdex-sets.json`, `extra-images.json` and `tcgdex-skipped.json` (it takes about two minutes; offer to run it). That's how new sets, and the images TCGdex adds weeks after a release, reach the site. Also remind him when a Featured Card Pool still uses `scrydexCard` or `pokemontcgCard` for a card the last run says TCGdex now has an image for (it no longer appears in `extra-images.json`), so the pool can switch to `poolCard`: Delta Reign's pool is waiting on that.
- Stay on free plans until the tool is solid. Move to Vercel Pro before any ads or payments go live, since Hobby is non-commercial only.

## Gotchas

- **Custom spacing scale** (`design/hutton-design-system.md`): Tailwind's numbered spacing doesn't mean the default sizes here, e.g. `p-4` is 16px, but `px-6` (64px) and `gap-5` (32px) are much bigger than usual. Round to the nearest step rather than writing arbitrary spacing like `mt-[12px]`.
- **No magic numbers** (`design/hutton-design-system.md`, section 12): let flex, grid, `aspect-ratio`, `clamp()` and container queries size things; name each fixed size once (a `--tb-*` size in `globals.css` or a TS constant); and ask Alex when a layout has a real choice.
- **`html` and `body` don't scroll** (`overflow: hidden` in `globals.css`). The page has its own scroll container.
- **Tailwind's `hover:` variant only applies on devices that can hover.** For hover effects that must work everywhere use plain `:hover` in CSS.
- **Tailwind's `shadow-[...]` stacks the shadow with four empty layers**, so animating `box-shadow` from it fades instead of moving. Set shadows that animate in plain CSS.
- **`@theme inline` tokens aren't real CSS variables** at runtime. Generated tokens are, but fonts use the `next/font` variables from `src/app/layout.tsx` directly.

Follow `design/hutton-design-system.md` using the `hutton-design` skill. Use the tokens, not raw hex.

## Files

All paths are in `src/app/`.

It only talks to graphics through `GraphicType`.

- `graphics/types.ts`: the `GraphicType` interface; `graphics/index.ts`: the list of types (`GRAPHIC_TYPES`), the `Graphic` union, and `typeOf(kind)`.
- `graphics/tier-list/`: `model.ts` (document, layout, edits, import, parse), `TierListCanvas.tsx`, `TierListSettings.tsx`, and `index.ts` (its `GraphicType`).
- `graphics/blank/`: the same for the blank canvas (`BlankCanvasView.tsx`, `BlankSettings.tsx`).
- `canvas/CardNode.tsx`: a card on the board for every graphic (image or split card, rounded clip, placeholder, dragging, menu clicks). `canvas/size.ts`: board, export and card sizes.
- `canvas/tray.ts`: the card tray's model (`Tray`, saved as each graphic's `tray`; layout, drop index, edits); `canvas/CardTray.tsx` draws it. The editor owns it for every graphic (see Card tray).
- `cards.ts`: card types saved in documents (`CardFace`, `CardItem`), `newId`, client calls to the API routes, bulk import lookups (`resolveCard`, `defaultPrint`), and image loading through the proxy.
- `importText.ts`: the bulk import format (documented at the top of the file): cards before the first `#` (the card tray, or the board: `ungroupedImport`), then `#` groups for the board.
- `ui/Button.tsx`: the page's buttons, with a `variant` (`default`, `primary`, `tool`, `icon`: square, holding only an icon, so it needs an `aria-label` and a `title`; `text`: just its words and an icon after them, brightening on hover).
- `ui/RadioBar.tsx`: the main nav. Each option has an icon from `public/`, drawn in the text color. A block in each option's color hugs the selected icon and word, measured from them, and springs to the next; left and right arrow keys move it. When the tabs don't fit, they show icons with only the selected tab named, then only icons (hidden labels are tooltips and stay for screen readers): hidden copies of the bar in each wider mode are measured against its space (`.sizers` in `RadioBar.module.css`), so the switch follows the real text widths. Labels fold and open by transitioning `max-width` to each label's measured width (`--label-width`), on the block's spring; the block's target comes from the hidden copy for the current step and selection, so it slides straight to where the name settles instead of chasing it.
- `ui/Checkbox.tsx`: every checkbox, drawn in CSS instead of the browser's own: a box in the fields' colors, ticked in the primary color with a dark check, or in a given `color` with a white or dark check (`check`, else by contrast), as the Sets popup's tier colors are. The row is the label; on touch screens it's a 44px touch target that gives the extra height back as negative margin (the Sets popup's rows keep it).
- `ui/ColorField.tsx`: a hex text field after a swatch that opens our own color picker in a floating popup like a dropdown's (`useAnchored`, `usePopup`), never the browser's native one: `react-colorful`'s `HexColorPicker` (a saturation and brightness square over a hue bar, restyled in `ColorField.module.css` through `:global`, its handles kept inside by insetting the part that reads the pointer, with a `::before` band that still takes presses at the edge), then Board Colors (as they were when it opened, so they hold still during a drag; the `BoardColors` context, which `Editor.tsx` fills with the board's tier colors, background, border, card tray color and white, one of each: `boardColors`), then a second hex field. Opening focuses the square (arrow keys move the color) except on touch screens; Escape, a press outside or Tab past it closes it, and Delete and Backspace in it don't reach the board. Dragging applies the color once a frame.
- `ui/SidebarHandle.tsx`: the sidebar's resize handle (from `b8` up). Saves the width as a share of the window in `localStorage` (`tierbinder-sidebar`) and sets it on the sidebar column (`.sideColumn`: the header and the sidebar) as `--tb-sidebar-width` (a `vw` value), which that rule in `Editor.module.css` uses, falling back to `--tb-sidebar-default`. `Editor.tsx` sets that default on the column from the main nav's measured full width (`RadioBar`'s `onFullWidth`), plus 8px each side and the edge line, so the nav fits with every label; `globals.css` has a 368px stand-in until then. Its limits are a `clamp()` in that CSS: at least `--tb-sidebar-min` (250px) and at most the window less `--tb-workspace-min` (`b5`, 512px), the minimum winning; a drag past either is saved at the limit, and the readout shows the width the sidebar really has. Double-click resets; it's also a focusable `separator` (WAI-ARIA window splitter) that the left and right arrows move.
- `ui/SearchFilters.tsx`: the card search's Sets button (the filter icon, then "Sets", the ticked set's code, or the first one's and how many more: "TWM +2") and popup (a search of set names and codes, with a clear button while it has text, over a scrolling list of every set to tick; ticked boxes (`Checkbox`: a white check on the default tier colors, else white or dark by contrast) take the board's tier colors in the order they were ticked, looping, or a new tier list's on the blank canvas), opening like a dropdown, scrolled to put the first ticked set in the list at the top. Opening focuses its search except on touch screens (it would bring up the keyboard over the list); on touch screens each row is a 44px touch target (`--tb-touch-target`). The popup floats, as the dropdowns' lists do (`ui/anchored.ts`). `searchOptions.ts`: the search's options (`sets`, `reverse`), `MAX_SETS` (40: the route refuses more, and the popup stops ticking there), and how they travel as `/api/search` query parameters (`sets=TWM,PRE`, sorted so the same sets share a cached URL; `reverse=1`). `sets.ts`: the sets to filter by, one per code, newest first, from `api/tcgdex-sets.json`, leaving out codes marked `empty`.
- `ui/anchored.ts`: `usePopup`, the open state every floating popup shares (the dropdowns, the Sets popup, the color picker): kept on screen `FOLD_CLEARANCE` while it folds closed, and closed by a press outside its box. `useAnchored`, which shows a popup (a `popover`, styled `.tierbinder-anchored` in `globals.css`) in the top layer under its button, so it floats over the board instead of being clipped by, or widening, the sidebar: the button's edges and width and the popup's width go to the CSS (`--anchor-*`, updated on scroll and resize), which keeps it 8px inside the window. It opens above the button instead when it doesn't fit below and there's more room above (`data-side`), and dropdown lists scroll when the window is too short. A button whose popup is open (`aria-expanded`) keeps its hover color.
- `ui/flights.ts`: `launchFlights`, cards flying from the sidebar to the board or the card tray (copies drawn in plain DOM over the page, `flights.module.css`), and `wholeOnScreen`; see Flying in.
- `ui/Dropdown.tsx`: a labeled dropdown (the Add to picker and the board type) in place of a native `<select>`, where an option with a `color` shows it as a swatch before its name (the tiers: a rounded box as big as Feather's square icon, in an icon-sized space, with a light stroke in `--tb-muted` when the option is `outlined`, as the card tray's is, since it's a shade of the board; its list's rows have 8px at each end; a hidden label becomes the tooltip; `chevron={false}` drops the arrow, as the Add to picker does), so it can open and close with the card menu's animation (top to bottom); arrow keys, Enter/Space and Escape work as in a select.
- `THIRD_PARTY_NOTICES.md` (repo root): the licenses of TCGdex's data and Feather's icons, and the Pokémon trademark disclaimer. The sidebar's foot (`ui/Credits.tsx`, under every tab) says "Cards from TCGdex" with an info button 4px after the link, as tall as the text, that opens the full credits and the disclaimer (TierBinder isn't affiliated with Nintendo, Creatures, GAME FREAK or The Pokémon Company) in a floating popup (`useAnchored`), until the credits get a better home.
- `text.ts`: `titleCase`, for labels kept in sentence case in code (see Capitalization in the design system).
- `color.ts`: contrast helpers for drawing on user-chosen colors (`luminance`, `darkReadsBetter`), used by the Sets ticks and the card tray's hint.
- `Loader.tsx`: loads `Editor` with `ssr: false` (Konva needs a browser canvas).
- `layout.tsx`: the root layout: fonts (Inter Black for tier labels, Figtree for the controls), metadata, analytics and the scroll container.

- `api/`: `card` (by set + number), `search` (by name, or every card in some sets), `image` (proxy); `cardSource.ts`, which they call, which filters and sorts what `tcgdex.ts` finds (the TCGdex API, with `tcgdex-sets.json`: set codes, names and dates, also used by the page for the set filter, and `extra-images.json`, read only by the API: images for cards the API gives none, both from `npm run tcgdex:sets`, which also lists the TCG Pocket sets it leaves out in `tcgdex-skipped.json` so lookups don't take them for new sets).

## Graphic types

A type (`GraphicType` in `graphics/types.ts`) owns its document, how it draws, its settings and where cards go; the editor owns everything else. What the editor asks of a type:

- `ungroupedImport`: where bulk import's cards before the first `#` go, `tray` or `board` (as one more group in front).
- `create`, `parse` (a saved graphic of its kind, with later settings filled in), `label` (in the board type dropdown), `targetNoun` (as in "Add to tier").
- `Canvas`: Konva layers drawn inside the editor's stage (passing `arriving` on to `CardNode`'s `hidden`, for cards flying in), with a `Rect` named `background` (pressing it deselects) and cards drawn with `CardNode`. It gets callbacks to change the graphic, select cards, open the card menu, pick a target and open a setting, and `onCardDrop`, which a dragged card's drop goes through first: it returns true when the editor took the card into the card tray, and the graphic leaves it be.
- Every graphic's document has a `tray` (`parseTray` in its `parse`, `defaultTray` in `create`, with the type's own default color), and a `border` the tray uses for split cards.
- `Toolbar` (optional): tools beyond moving cards, shown under the board. The editor keeps the active tool (`DEFAULT_TOOL`, `move`, until the toolbar picks another; reset when the board type changes) and passes it to the canvas as `tool`.
- `Settings`: its part of the Customize tab. `onEditSetting(key)` from the canvas switches to the Customize tab and passes `focus` to it (the tier list uses `tier:<index>`).
- Cards: `layout` (every card with its top-left corner and box, drawing order; the editor uses it for selection, hit-testing drops and export), `mapCards` (change or remove), `targets` (the Add to choices, each a name and an optional color for its swatch; hidden when there's only one), `addCard` (to a target), `dropCard` (at a point), `importCards` (bulk import's `#` groups). Adding returns the new graphic or `{ error }` (a tier or the card tray is full), shown as a toast: one short message at the top of the window that fades after `TOAST_DURATION` (3s, plus `TOAST_LINE_DURATION`, 1.5s, for each line past the first). Every message is a toast, never text on or under the board: full tiers and tray, bulk import ("Importing…", which stays until its result replaces it, then how many cards went where and a line for each problem, up to `MAX_TOAST_PROBLEMS` (4) and then how many more; "Couldn't Import; Try Again" if a lookup fails outright) and copying. The screen reader copy is a new element each showing, so the same message again is read again. Only one shows at a time: another message replaces it, and the same one again restarts its timer without replaying its entrance, so rage clicks don't pile up (`toast` in `Editor.tsx`, `.toast` in `Editor.module.css`). Screen readers get it from a hidden live region that's always mounted; the visible toast is `aria-hidden`.

### Adding a graphic type

1. Add `graphics/<kind>/` with a model (document type with a unique `kind`, defaults, parse, layout and edits), a canvas, settings, and an `index.ts` exporting its `GraphicType`.
2. Add it to `GRAPHIC_TYPES` and to the `Graphic` union in `graphics/index.ts`. The board type dropdown lists it, and saves of it load with no other changes.
3. Add its notes below.

## The board

- 1200×675 for every graphic; export is 2× (2400×1350 PNG, or taller with the card tray: 2400×1690 with up to 10 cards in it), downloaded (named after the graphic's kind) or copied.
- On screen the stage scales to fill the workspace, larger or smaller than 1200 (`scale` in `Editor.tsx`): its width on narrow screens, and from `b8` up as much as fits beside the sidebar, with room left for the toolbar, which it measures rather than assumes.
- Cards are 100×140, clipped to the card images' rounded corners (`CARD_CORNER_RADIUS`, ~4.5px).
- Editor-only layers are named `editor` and hidden while exporting: the editor's (selection outline, and the `drag` group the dragged card moves into), and any a graphic adds (the eraser's circle). The editor's layer listens, so a dragged card's events still reach the stage and move the outline with it; the outline itself doesn't (`listening={false}`).
- The selection outline follows a dragged card: Konva moves the card without React, so the stage's `dragmove` and `dragend` move the outline too. Cards carry their item's id (`CardNode` sets the group's `id`), which is how the editor knows the dragged card is the selected one.
- Canvas text uses Inter Black (900), loaded with `next/font` in `layout.tsx` (`--font-inter`); it needs `document.fonts.load` before it draws, so the editor passes `fontFamily` once it's loaded.

## Tier list

- Always 4 tiers, at most 12 cards per tier. New tier lists start with Goated, Solid, Mid, Fraud.
- Cards have a 25px gap that shrinks (negative overlaps, later cards on top) once a row is full; 8 fit at the default gap.
- Settings: `background`, `border` (the lines between tiers, and split card dividers and strokes) and `tierCardBorders` (a 3px stroke inside each card in its tier's color).
- Tier labels are Inter Black at 30px. Names wrap at spaces in `wrapLabel`, never mid-word (Konva's own wrap splits words). `\n` in a name is a line break.
- Dragging a card moves or reorders it (`dropTarget`, `moveCard`). A search result dropped on the board goes in the tier under the pointer, before the first card whose center is to its right.
- Clicking a tier's row anywhere but on a card (its label, the empty space) makes it the Add to tier. Cards are Konva groups named `card`, which is how the canvas tells them apart.
- Bulk import adds each `#` group to the next tier, after the cards already there, and renames the tier if the group has a name. Cards past 12 and groups past the fourth are left out and reported; it never clears the board. Cards before the first `#` go in the card tray instead (`parseImport` returns `tray` and `groups`); one Import button does both.
- Double-clicking a tier label switches to the Customize tab and focuses that name.

## Blank canvas

- Cards placed anywhere: each item is a `CardItem` with its top-left `x`, `y`, kept wholly on the board. Later cards draw on top, and a moved card goes on top.
- Cards added from search or import fill a grid of as many spots as fit at the card size (10 × 4 at the default), by how many cards there are, starting over once full; a dropped result is centered on the pointer. Import groups mean nothing here, and cards before the first `#` land on the canvas too (`ungroupedImport: 'board'`), not in the card tray.
- Ink is clipped to the board, so it never draws over the card tray.
- Settings: `cardWidth` (Card Size, 40–400px wide; the field applies once a typed number is in range), `topHalf` (Show only top half of cards), `background` (white by default), and `border` for split cards' divider and stroke. Changing the size or top halves moves cards that would hang off the board back onto it.
- Tools (`BlankToolbar.tsx`, under the board): Move (the default: drag and click cards), Pen (color, size; default near-black `#1b1b1b`, 12px) and Eraser (size; default 24px). Pen and eraser settings are saved with the board.
- Ink: `strokes` (pen or eraser, with Konva `Line` points rounded to 0.1px) on their own layer above the cards. Eraser strokes use `destination-out`, so they remove only ink, never cards or the background. While drawing, a transparent rect on the ink layer takes every press (cards don't move or open menus), the stroke stays in component state until the pointer is released anywhere, and a click leaves a dot (the point is doubled). The pen shows a crosshair; the eraser hides the pointer and draws its size as a circle in an editor-only layer. Clear board clears the ink.
- `CardNode` draws every card at 100×140 and scales it (`width`), so borders and corners scale too; `topHalf` clips to the top half. Split cards always show both halves, at full height, since their top half would hide the bottom card. `cardBox` gives the box a card takes, which the canvas reports in `layout` for the selection outline and drop hit-testing.

## Card tray

- An optional holding area under the board, for every graphic, each board keeping its own (`tray`: `enabled`, `color`, `items`). Turned on in Customize ("Show card tray under the board", then "Tray Color"); turned off, its cards stay saved and come back. It shows at every width: on phones it's under the board in the page, scaled with it.
- Drawn in the same stage as the board, `TRAY_GAP` (16 on-screen px) under it, as wide as the board and as tall as its cards and 15px padding (`trayHeight`: 170 for a full-size row, about as tall as a tier), with `TRAY_RADIUS` (8 on-screen px) corners. The stage grows to hold it, and the board's scale fits both.
- Up to 48 cards (`MAX_TRAY_CARDS`), each row filled left to right before the next: up to 10 at full size in one row; then shrinking to fit it, down to 75% (`MIN_ROW_SHARE`, 14 cards); then a second row at 75% (up to 28); then both rows shrinking to fit (48 are two rows of 24). The tray's height follows (137 at 14 cards, 248 for two rows at 75%), so the board rescales as cards come and go, and the export's height changes with it.
- A card dragged between the board and the tray grows or shrinks (300ms, easing out) to the size where its center is: the board's (`cardWidth` on the `GraphicType`, else `CARD_WIDTH`) or the tray's with one more card (`trayCardWidth`), keeping its center under the same spot of the pointer (`CardNode`'s `dragWidth`, given to the graphics as `cardDragWidth`). The selection outline takes the card's size as it changes, and the drop is reported at the laid-out size around the card's center.
- It works like a tier: "Card Tray" is the last Add to choice (with its color as the swatch, outlined), even while the tray is off: adding a card to it turns it on (`withTray` sets `enabled`); clicking its empty space picks it, results dropped on it go in by position, and cards drag between it and the board (into the tray by their center; out of it, the graphic's `dropCard` at the card's center) and reorder within it. While a card is dragged, `CardNode` moves it alone into the `drag` group at the bottom of the editor's layer (above the board and the tray, below the outline) and back into its own layer and place on the drop, redrawing the layer it left each time (Konva doesn't); a card removed mid-drag (Delete, or the tray turned off) ignores its drop. A board card dragged over a full tray keeps its size. A result dropped on a tray card offers "Add to Card Tray". The card menu opens upward from tray cards, at the board's foot. While the pen or eraser is active the tray takes no presses. On a tier list (`ungroupedImport: 'tray'` on the `GraphicType`), bulk import puts the cards before its first `#` line in it, in order, as many as fit (adding any turns the tray on: `importTrayCards`). Its toast says how many cards went where ("Added 5 Cards to the Card Tray"), then any problems. The import is placed on the board as it is once the lookups finish (`docRef`). Clear board empties it if it shows, keeping it on (its confirmation then says "Clear the Board and Card Tray?"); a tray turned off keeps its cards.
- Empty, it shows Feather's info icon (drawn in Konva, as tall as the text, 4 on-screen px before it) and "Send Cards to Card Tray to Hold Them" centered together in its middle (`TrayHint` in `CardTray.tsx`, `TRAY_HINT`), 14 on-screen px of Figtree, white at 45% or Petrel 950 at 60%, (whichever reads on the tray, `darkReadsBetter` in `color.ts`), named `editor` so exports leave it out. Once a card has been in a tray it isn't shown again for the tab's session (`tierbinder-tray-hint-seen` in `sessionStorage`, so a reload keeps it hidden).
- Save & Share's "Include card tray in export" (off by default, not saved) exports it flush and square under the board: 2400 wide and 1350 plus twice the tray's height tall (1690 with up to 10 cards; `trayHeight` is whole pixels). The export draws the stage at scale 1 and `pixelRatio: EXPORT_SCALE`, so it's always whole pixels, moving the `tray` group up and squaring its `trayBox` just while drawing, all put back before the screen next draws.

## Split cards

- A `CardItem` with `split` (its bottom `CardFace`). Drawn as the top halves of both cards (each image's top 50%, 70px tall) over a backing in the divider color, with a 3px divider and a 3px inner stroke, both in the graphic's border color (or the tier's color when tier borders are on).
- Made from the card menu, by dropping a result on a card, or imported as `Top card / Bottom card`; both halves must be found.

## Editing

- Clicking a card without dragging (Konva's `click`/`tap` don't fire after a drag) opens the card menu, HTML over the board; so does right-clicking a card (the browser's own menu is prevented on cards only). Konva also fires `click` for the right button, so only a left `click` opens the menu; right-click opens it from `contextmenu`, which would otherwise land on the already-open menu:
  - The menu stretches out to the right from its left edge (`.tierbinder-menu` in `globals.css`) on `--ease-spring`, and on close folds back to its left edge in 180ms, fading over the last part (`shownMenu` keeps the last menu on screen for `FOLD_CLEARANCE` (220ms, `ui/motion.ts`, shared by every closing popup), on a timer since `animationend` doesn't fire in a tab that isn't painting). It's keyed by card and position, so each opening replays the animation.
  - Card: View, Remove Card, Replace Card, Make Split Card (written in sentence case in code, since they are the menu's keys, and title-cased where shown: `titleCase` in `text.ts`).
  - Split card: View, Remove Card, Replace Top Half, Replace Bottom Half, Swap Halves, Unsplit (keeps the top).
  - A search result dropped on a card opens the menu with the result's choices (`cardMenu.dropped`): Add as Split Card (the result is the bottom half) or Add to Tier/Canvas (the graphic's `dropCard` at the drop point); on a split card, Replace Top Half, Replace Bottom Half or Add to tier/canvas.
  - View (focused when it opens, as a modal dialog, and handing focus back when it closes) shows the card large in the middle of the window over a dimmed page (as tall as `--tb-view-height`, narrower to fit; a split card shows both cards side by side), growing from its place on the board on the spring and shrinking back to it when anything is pressed or Escape; it's modal: keys stop at it (so Delete can't remove the card behind it), Tab stays on it, and the sidebar column and workspace are `inert`; closing hands focus to the board (`boardBoxRef`, focusable, no ring), with the card still selected and its menu closed (`viewing`/`shownView` in `Editor.tsx`, kept on screen `FOLD_CLEARANCE` while it closes, like the menu).
  - Replace and Make split card switch to the Add Cards tab and put it in picking mode (`picking`: `{ id, part: 'top' | 'bottom' }`): replacing searches that card's name, and the next result clicked takes its place (or becomes the bottom half), until Cancel or Escape. Making a split card (the bottom half of an unsplit card) shows in the Add to picker instead of a message and Cancel, when it has more than one choice: a white card-shaped swatch (`SPLIT_SWATCH`) and "Splitting <name>" (`splitPicker`, Dropdown's `current`), with no option selected; picking any target cancels it. Screen readers hear it through a hidden status: "Splitting <name>: pick the bottom card from the results, or a tier to cancel."
- The Add Cards tab: clicking Add Cards in the main nav while it's showing focuses the search. ## Flying in

- A card added by clicking a search result (or its menu's Add to choices) or a featured pool flies in, unless motion is reduced: a copy of it leaves its thumbnail for its spot on the board or in the card tray, along a slight arc (`FLIGHT_ARC`, 15% of the distance at its middle, bowing toward where it lands: down to a lower spot, up to a higher one) on `--ease-flight` (ease in and out, no overshoot) over `--duration-flight` (500ms), a pool's `FLIGHT_STAGGER` (40ms) apart, its own card hidden until it lands (`arriving` in `Editor.tsx`, `CardNode`'s `hidden`). `flyIn` in `Editor.tsx` starts them; `ui/flights.ts` draws them in plain DOM over the page (`.flight`, above the toast), reading the board's place once a frame so they follow it as it rescales or scrolls, and landing them in one update a frame.
- A result's card whose spot is off screen (on a phone, the board is scrolled away above the results) appears there at once. A pool's cards instead scroll the board's foot into view first (`scrollIntoView`, waiting for `scrollend` or `SCROLL_WAIT`, 800ms), then fly up to the tray from wherever their thumbnails now are; the scroll is skipped when the last new card's spot is wholly on screen, and a thumbnail no longer shown (its panel hidden, or replaced by a search) leaves its card to appear at once.
- They always land: a timer lands any left when frames stop (a hidden tab, where the copies stay until it draws again, unseen), exports land them first, and so does leaving the page. A copy shows what its thumbnail loaded (the proxy, if the CDN failed). Dragging a result and bulk import don't fly. Under reduced motion nothing flies, but a pool still scrolls the tray into view, at once.

## Look and motion

- The palette, look and motion are in `design/hutton-design-system.md`, including `--ease-spring`, `--duration-move`, `--duration-drop` and `--duration-fade`.
- The type scale (`text-field`, `text-body`, `text-caption`) is in the `@theme` block at the top of `globals.css`, since the token generator has none. Fields are 16px on phones, because iPhones zoom the page on smaller ones.
- Capitalization (section 4 of the design system): title case for headings, tabs, buttons, menu items, dropdown options, field labels and messages (no closing period; the API routes' errors too, and the search turns the browser's own network errors into "Couldn't Reach the Server"); sentence case for checkbox labels, placeholders, tooltips and screen reader text.
- Scrollbars (the page's and every panel's) are thin, a rounded `--tb-scroll-thumb` on no track (`globals.css`), drawn with `scrollbar-color` where it's supported and the WebKit scrollbar in Safari.
- Popups (the card menu, the search result menu and its flyout, dropdowns, the Sets popup and the color picker) share `.tierbinder-menu` in `globals.css`; those listing options (the card menu, the result menu and its flyout, and the dropdowns' lists) are `.tierbinder-list`: options as rounded rows inset 4px, lighting up in `--tb-option-hover`, with 8px corners on the card menu and 4px on dropdowns; the dropdowns, the Sets popup and the color picker float in the top layer (`ui/anchored.ts`).

## Cards from TCGdex

- Card data and images come from the TCGdex API (tcgdex.dev: free, no key, open source), called from our API routes. Pokémon TCG Pocket sets are left out.
- TCGdex is the card source (search, set listings, lookups), and searches fail while it's down. A card its API gives no image takes one from `extra-images.json` (by TCGdex set id and card id, the board's image and the thumbnail), or is left out (MEP promos past the first 40, MEE, the Classic Collections, some other promos). `npm run tcgdex:sets` fills it, checking every image loads: first TCGdex's own, when its asset host has one anyway, in the set's folder (some MEP, SVP and Shining Legends cards) or a subset's main set's (the Shiny Vault, Galarian Gallery and Trainer Galleries); then pokemon-tcg-data's, on `images.scrydex.com` and `images.pokemontcg.io` (the newest set until TCGdex has it, Shining Legends, Dragon Majesty, promos, energies, some McDonald's collections and more). The site never calls pokemon-tcg-data: the script reads its JSON from GitHub and matches each card by set code (its promo codes differ: `PR-SV` for `SVP`; sets without a code by name), unpadded number and name, skipping any whose name doesn't match. A card TCGdex later gets an image for drops out of the file on the next run. Sets whose TCGdex listing doesn't match the cards are left out (`MISNUMBERED` in `tcgdex.ts`: 30th Classic Collection, numbered 1-30 in another order there, `CC1`-`CC30` on the cards).
- Cards are saved and imported by their official set code and printed number (`TWM 130`, `SIT TG05`); TCGdex's own set ids (`sv06`) stay inside `api/tcgdex.ts`. `api/tcgdex-sets.json` maps ids to codes, names and release dates (and marks `empty` the codes with no cards to show: none with an image from either source, like the trainer kits, which the set filter leaves out), since TCGdex only gives them one set at a time; sets released since it was generated are looked up when they first appear. Run `npm run tcgdex:sets` now and then, and after each new set, and commit the three files it writes (see Workflow for the reminder) (in the cloud container it needs `NODE_USE_ENV_PROXY=1`). Subsets share their main set's code (`SIT:TG` → `SIT`), and one code can cover several TCGdex sets (30th Celebration and its Classic Collection are both `30C`).
- TCGdex pads some numbers (`073`); they're saved as printed (`73`).
- What TCGdex is missing, and why (checked November 2026): a new set's images arrive a few weeks after its data (Pitch Black took about 2½ weeks). The Shiny Vault, Galarian Gallery and Trainer Gallery images are on its host under the main set (`swsh12.5/GG36`), but its API looks under the subset and leaves them out ([tcgdex/cards-database#2126](https://github.com/tcgdex/cards-database/issues/2126)); `npm run tcgdex:sets` picks them up there. Shining Legends, Dragon Majesty, both Classic Collections, MEP promos past the first 40, the SVE and MEE energies and the e-Card crystal cards have no images there at all. Missing images are reported on [#2341](https://github.com/tcgdex/cards-database/issues/2341) and uploaded through its ingest page; its contributing rules forbid AI-assisted data, and AI-assisted code must be marked (their `AGENTS.md`).
- TCGdex's rules: GET requests over HTTPS, no key, no hard rate limit ("please be considerate", cache rather than refetch), WebP recommended; its database is MIT (notice in `THIRD_PARTY_NOTICES.md`); its images have no stated license.
- pokemon-tcg-data (the JSON behind pokemontcg.io, on GitHub, kept by Scrydex) has no license, and its images are Scrydex's to host or cut off; its API is deprecated, with keys ending March 1, 2027, and the repo will likely stop being updated or allowed at some point. If it goes, the fill-in images stop loading (search and the board show what TCGdex has) and we need another source: Scrydex's paid API ($29/month and up) is the plan once there's revenue, or keeping our own copies. Scraping (Limitless, pokemon.com) is what was removed and stays out.
- Every image is loaded through `/api/image`, which keeps canvas export working and caches images. The proxy only allows the hosts listed in its route. TCGdex images are `high.webp` (600×825) on the board and `low.webp` in the results, pokemon-tcg-data's its large (about 733×1024) and small images; search thumbnails load from the source directly and retry once through the proxy if they fail; a result whose thumbnail fails both ways is hidden (TCGdex lists some images it doesn't have, like 30C's R, G and B Mews).
- Search matches names containing the query. Results are newest set first, then by set code and number (in numeric order: CC2 before CC10), and named from TCGdex.
- Search filter and order (`searchOptions.ts`): results are by release date, newest set first (then set code and lowest number first); reversed, all of it flips (oldest set first, each from its highest number down). The sort button's tooltip says "Sort: Newest first"/"Sort: Oldest first", or "Lowest/Highest number first" with one set ticked. The set filter keeps only the ticked set codes (a code includes its subsets, so `LOR` brings its Trainer Gallery); both are done in `cardSource.ts` after the search. With no name, the search lists the ticked sets whole (up to 40): TCGdex's `/sets/{id}` (every set with that code). Sets newer than `tcgdex-sets.json` can be searched but aren't listed in the filter until it's regenerated. A name-only import picks the lowest number in the newest set, skipping special reprint sets (`SPECIAL_SETS` in `cards.ts`: 30th Celebration and Celebrations) and subset numbers like TG05 while a regular print exists.

## Saving

- The document autosaves to `localStorage` (`tierbinder-doc`) and is read back with `parseSaved`; there's no file save/load. It holds one board per type (`graphics`, keyed by kind) and which one is showing (`kind`, whose board is always present). Cards are saved as names and image URLs, so even full boards are a few KB. The image proxy only allows today's hosts, so a board saved with Limitless image URLs (before November 2026) would show those cards as placeholders; no such boards were in use when Limitless was dropped.
- Version 1 was a tier list on its own (`{ version: 1, kind: 'tier-list', ... }`) and version 2 one graphic (`{ version: 2, graphic }`); `parseSaved` converts both. A saved board that doesn't parse is dropped and starts new, keeping the others.
- Changing the document's shape means bumping `version` and converting in `parseSaved`; a graphic's new setting with a default can instead be filled in by its `parse` (as the tier list's `border` and `tierCardBorders` are).
- In `next dev`, a tab left open while the document shape changes keeps its old in-memory board (without the new fields) until it's reloaded.

## Testing in the in-app browser

- It doesn't paint: screenshots time out and Konva's hit canvas goes stale. Call `stage.draw()` before simulating clicks on the board, and read results from `localStorage` or the Konva tree (`Konva.stages[0]`). Pixels can be checked with `stage.toCanvas()`; hashing them before and after a refactor checks nothing changed.
- Simulated mouse drags don't start Konva drags; to test a card drop, set the card node's position and `fire('dragend')`.
- CSS animations start but don't advance, and `animationend` never fires; check where one ends with `el.getAnimations().forEach((a) => a.finish())`.
- `confirm()` returns false at once and `alert()` never shows, so confirm on the page instead (see Clear board).
- Every tab shares the saved board: back up `tierbinder-doc` before a test that edits it, restore it after, and test in a background tab rather than the one being used.
